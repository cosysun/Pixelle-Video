    已有 NGINX 部署的配置精简¶

    用户随后明确证书和域名由现有 NGINX 管理。已从 .env 和 .env.example 删除自带网关的证书/端口配置，以及公共 URL、Cookie 开关和可信代理网段三项配置；上方示例域名的阻塞记录已不适用，登录哈希仍需填写。

    应用通过保留的 Host 校验浏览器 Origin，默认 HTTPS 来源及 Secure Cookie，不依赖内网请求协议或代理头。NGINX 必须使用 proxy_set_header Host $http_host。默认关闭代理头解析；需要逐客户端 IP 限流时才额外配置可信代理。本机直接 HTTP 开发仍可选择设置 PIXELLE_COOKIE_SECURE=false。

    认证及来源校验专项 10 项通过：验证内网 HTTP 接收外部 HTTPS Origin、默认 HTTPS 端口等价、拒绝外域/HTTP 降级/错误端口/非法 Origin，以及 Cookie 在 HTTPS 上使用。已验证 Compose 的同机、内网绑定和自带 NGINX 三种配置能够解析；实际网关访问待部署后验收。

    登录密码配置简化¶

    按用户要求，将 .env 和示例中的 PIXELLE_PASSWORD_HASH 替换为直接填写的 PIXELLE_PASSWORD，移除生成密码哈希的操作命令。服务启动时在内存中生成校验值，登录仍使用同域会话 Cookie；密码不写入 SQLite 或接口响应。错误脱敏覆盖新的密码环境变量。

    上方历史记录中的“需要填写登录哈希”已被此变更替代。现在只需在本机 .env 填写 PIXELLE_PASSWORD 并重启应用。

    平台测试 28 项通过，包含直接密码登录、中文及特殊字符密码、错误密码拒绝、缺失密码阻止启动和密码错误信息脱敏；Ruff、Python 编译、Compose 配置解析及差异空白检查通过。
